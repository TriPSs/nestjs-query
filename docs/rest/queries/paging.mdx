## Offset paging

Offset paging is the default REST strategy. The endpoint accepts:

- `limit`: maximum number of records to return. The default is `25` and the default maximum is `100`.
- `offset`: zero-based number of records to skip. The default is `0`.

```http
GET /todo-items?limit=25&offset=50
```

```json
{
  "pageInfo": {
    "hasNextPage": false,
    "hasPreviousPage": true
  },
  "nodes": []
}
```

Configure paging on the DTO or endpoint:

```ts
import { SortDirection } from '@ptc-org/nestjs-query-core'
import { PagingStrategies, QueryOptions } from '@ptc-org/nestjs-query-rest'

@QueryOptions({
  pagingStrategy: PagingStrategies.OFFSET,
  defaultResultSize: 20,
  maxResultsSize: 100,
  enableTotalCount: true
})
export class TodoItemDTO {}
```

When `enableTotalCount` is `true`, the connection also contains `totalCount`. Counting may add a database query, so enable it only when clients need it.

## No paging

Use `PagingStrategies.NONE` to return all matching records as a JSON array:

```ts
{
  DTOClass: TodoItemDTO,
  EntityClass: TodoItemEntity,
  pagingStrategy: PagingStrategies.NONE
}
```

```json
[
  { "id": 1, "title": "Write docs", "completed": false },
  { "id": 2, "title": "Review docs", "completed": true }
]
```

Use this strategy only for bounded collections.

## Sorting

Use `sort=field:ASC` or `sort=field:DESC` to sort by a property decorated with `@FilterableField`. Repeat the parameter for multiple fields; the order of the parameters determines sort priority. Sorting is supported on paged, unpaged, and CSV export endpoints.

```http
GET /todo-items?sort=completed:ASC&sort=id:DESC
```

Optionally append `:NULLS_FIRST` or `:NULLS_LAST` to control null ordering when supported by your persistence adapter:

```http
GET /todo-items?sort=title:ASC:NULLS_LAST
```

Directions and null-order options are case-sensitive. Unknown fields and malformed sort values return HTTP 400. Only filterable DTO properties can be requested, including inherited properties.

When `sort` is omitted, the server uses `defaultSort`. Client sorting replaces the default sort list:

```ts
@QueryOptions({
  defaultSort: [
    { field: 'completed', direction: SortDirection.ASC },
    { field: 'created', direction: SortDirection.DESC }
  ]
})
export class TodoItemDTO {}
```

Set `disableSort: true` in query options to remove the client sort parameter and always use `defaultSort`. The client sort parameter is also omitted when the DTO has no filterable fields. Server-configured defaults are not restricted to filterable fields.

Always add a stable tie-breaker (commonly the ID) when records can share the same sort value, especially when using offset paging.
