---
title: 'CSV Export'
description: 'Export filtered and authorized REST query results as CSV.'
---

Every generated CRUD controller includes a `GET /<basePath>/export` endpoint unless export is disabled. The endpoint accepts the generated filters and, when search is enabled, the optional `query` search term. It uses the configured default sorting, runs the collection query hook, applies the authorization filter, and respects the configured soft-delete visibility.

For an endpoint with `basePath: 'todo-items'`, request matching records with:

```http
GET /todo-items/export?completed=false
Accept: text/csv
```

```csv
"id","title","completed"
1,"Write REST documentation",false
2,"Review examples",false
```

The response uses the `text/csv` content type and includes a header row when records are returned. An empty result produces an empty response body. String values are quoted, and values that could be interpreted as spreadsheet formulas are escaped.

## Configure exports[​](#configure-exports 'Direct link to Configure exports')

By default, an export returns at most `1000` records. You can change this limit and customize the generated route without affecting the collection endpoint:

```ts
{
  DTOClass: TodoItemDTO,
  EntityClass: TodoItemEntity,
  basePath: 'todo-items',
  export: {
    limit: 5000,
    many: {
      path: 'reports/todo-items',
      description: 'Download visible todo items as CSV'
    }
  }
}
```

The controller appends `/export` to `many.path`. Combined with `basePath`, the example above is available at `/todo-items/reports/todo-items/export`.

Disable the export endpoint while keeping the other CRUD endpoints enabled with:

```ts
{
  DTOClass: TodoItemDTO,
  EntityClass: TodoItemEntity,
  basePath: 'todo-items',
  export: { disabled: true }
}
```

## Export a different shape[​](#export-a-different-shape 'Direct link to Export a different shape')

By default, the controller serializes the decorated fields from `DTOClass`. Set `ExportDTOClass` to choose a different set of CSV columns without changing the DTO used by the other CRUD endpoints. Each decorated property becomes a column, and its property name becomes the CSV header.

```ts todo-item-export.dto.ts
import { Field } from '@ptc-org/nestjs-query-rest'

export class TodoItemExportDTO {
  @Field()
  id!: number

  @Field()
  title!: string

  @Field()
  completed!: boolean
}
```

```ts
{
  DTOClass: TodoItemDTO,
  EntityClass: TodoItemEntity,
  basePath: 'todo-items',
  export: { ExportDTOClass: TodoItemExportDTO }
}
```

The generated controller loads the selected records and builds the CSV response in memory. Keep the export limit bounded; for very large datasets, implement a custom controller that streams the response.
