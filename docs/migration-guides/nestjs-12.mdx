---
title: 'Upgrading to NestJS 12'
description: 'Migrate to NestJS 12 and @nestjs/graphql 14: relation and field name collisions, and subscription authentication.'
---

`@ptc-org/nestjs-query-graphql@11.1` and later support NestJS 12 with `@nestjs/graphql@14`. Note that `@nestjs/graphql@14` requires `@nestjs/common@^12` strictly, so NestJS 10 and 11 stay on `@nestjs/graphql@13` — both pairings are supported. CommonJS projects also need Node.js >= 20.19 (the first release with unflagged `require(esm)`) to load the Nest 12 packages.

## Relation and field name collisions

An explicitly declared field takes precedence over a relation with the same name on the same DTO. In `@nestjs/graphql@13` the relation used to win instead. If a DTO declares both — for example a class-level `@Relation('lender', () => LenderDto)` and a `@FilterableField(() => GraphQLObjectID, { nullable: true }) lender: string` — the generated schema will silently change after the upgrade. Remove the duplicate declaration and keep only the one you actually want exposed. See [issue #532](https://github.com/TriPSs/nestjs-query/issues/532) for details.

## Subscription authentication

If you migrate your subscriptions to the `graphql-ws` protocol as part of the upgrade, authentication no longer flows through `onConnect`: its return value is only the connection-ack payload and never reaches resolvers. Expose the connection params as headers through `context` instead.

```ts
import { Context } from 'graphql-ws'

GraphQLModule.forRoot({
  driver: ApolloDriver,
  subscriptions: {
    'graphql-ws': {
      context: (ctx: Context) => ({ req: { headers: ctx.connectionParams ?? {} } })
    }
  }
})
```
